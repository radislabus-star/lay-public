# Firefox Double Shift: один экран, десять полей

Обязательный текущий протокол Firefox/Chrome:
[browser_ime_standard.md](browser_ime_standard.md). Chrome использует
[отдельный вход](chrome_double_shift.html) в ту же страницу и observer.
Переключатель «Проверка» добавляет пять быстрых жестов (десять Shift) к прежнему
сценарию туда/обратно. Скорость каждого жеста и сводка сохраняются в JSON;
браузерный таймер отличается от native timestamp отправки клавиши.
Выбор «Сценарий» содержит 15 планов: разные слова, Space в обе стороны,
чистое EN, опечатку/отмену, перенос буквы, Tab, курсор, выделение и фокус.
Точные ожидания перечислены в общем протоколе. Функциональные планы отключают
неприменимые режимы слова/серии и измеряют свои действия отдельно.
Описание семи шагов ниже относится к базовому «Туда и обратно».

Открыть `firefox_double_shift.html` в Firefox. Обычное, приватное и
полноэкранное окно проверяются отдельными проходами: выбор в странице — метка
пользователя, он не открывает окно и не определяет приватность/Wayland/X11.

1. Выбрать русскую раскладку Lay, режим слова и нажать «Начать».
2. Следовать текущей инструкции: физически набрать `привет`, Double Shift,
   клавиша Я/Z, Backspace, второй Double Shift, Я/Z, Backspace.
3. Нажать «Следующее поле». Фокус переводится на него, очищается только это
   тестовое поле. Переключения выполняются последовательно: клавиатура и IME
   обслуживают одно сфокусированное поле.
4. Если преобразования нет — Escape в активном поле (также внутри iframe)
   или мышью «Не сработало». Сохранить JSON после прохода.
5. Повторить отдельно со словом после пробела и в нужных режимах окна.

Типы: text/search/url/tel/email input, textarea, обычный contenteditable,
plaintext-only contenteditable, iframe input и iframe contenteditable.
Неподдерживаемый тип или недоступный iframe observer остаётся BLOCKED.
Пароли, защищённые поля и браузерная адресная строка сюда не входят.
Для всех десяти полей на одном экране нужна область страницы от900×600
при масштабе100%. В узком или меньшем окне остаётся прокрутка; увеличение
textarea пользователем также может изменить высоту страницы.

Каждому PASS_DOM предшествуют семь наблюдений, включая оба точных изменения
`привет → ghbdtn → привет`, две полные пары доверенных DOM Shift press/release
одной стороны и фактическая следующая буква в каждой раскладке. Нажатие Shift
с повтором от удержания не считается второй парой. Можно использовать левый
или правый Shift; стороны внутри одной пары не смешиваются.

Это проверка поверхности DOM: активная composition допустима и записана
отдельно, как и неизвестный caret у email. NBSP в редактируемых блоках
нормализуется к обычному пробелу для сравнения; rawText сохраняется. Нет
утверждения о committed text, daemon RPC/числе планов, GNOME icon или runtime
bytes. Их не может установить HTML. Программные dispatchEvent не дают PASS;
потеря фокуса, paste/drop и переполнение bounded capture останавливают case.
Все попытки и прежние FAIL/BLOCKED сохраняются. Сводка текущего batch не
смешивает предыдущие сценарии или метки окна. В JSON входит только собственная
тестовая страница; никаких сетевых запросов, backend/IME API, установки,
перезапуска, конвертации слова JavaScript или очистки обучения нет.

Source contract: `tests/test_firefox_double_shift_probe.py` запускает25 Node
семантических проверок observer, требует25PASS/0FAIL/0SKIP и проверяет все10
карточек вместе с фактическими тегами, типами и редакторами вsrcdoc. Эти тесты запускают
только удалённо под существующим resource guard; это не native Firefox PASS.
Локальный автоматический keyboard/IME прогон требует конкретного разрешения.
Разрешённая native-диагностика10октября и её FAIL/BLOCKED имеют отдельные
receipts в owning document; source PASS их не отменяет.
