## Same-name recreation source audit

The same-profile US -> US case depends on a public
`IBus.Bus.set_global_engine("lay-ime-us")` call creating a new real factory
engine even when `lay-ime-us` is already selected. The pinned IBus 1.5.34
source supports that assumption:

1. `src/ibusbus.c:2343-2362` implements `ibus_bus_set_global_engine()` as a
   synchronous public D-Bus `SetGlobalEngine` call.
2. `bus/ibusimpl.c:1808-1845` handles that public method by resolving the
   descriptor and unconditionally calling `bus_input_context_set_engine_by_desc`;
   this handler contains no same-name shortcut.
3. `bus/engineproxy.c:1030-1085` enters `bus_engine_proxy_new()` and uses the
   component factory, starting the component first when its factory is absent.
4. `bus/inputcontext.c:3152-3181` completes proxy creation by disabling the old
   context engine, installing the new proxy, and enabling it.

The superficially conflicting same-name no-op is the separate internal helper
`bus_ibus_impl_set_global_engine_by_name()` at
`bus/ibusimpl.c:1007-1038`. Its shortcut at lines 1020-1024 only re-enables the
existing engine. The observed callers at lines 1061 and 1071 are registry
fallback paths; the public `SetGlobalEngine` handler above does not call this
helper.
