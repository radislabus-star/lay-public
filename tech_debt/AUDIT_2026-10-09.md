## Найденные корни, факты и риски

1. **Очередь имеет несколько конкурирующих «текущих» состояний.**
   README начинает с R5/C20/1.0.72, CONTINUE — с R12/1.0.72 и ниже содержит
   конкурирующий latest R7. Поздние owning entries и опубликованный HEAD уже
   другие. TD-121 наверху имеет R12, а README объявляет R5 последним.
   Это доказанный долг управления доказательствами,
   способный отправить следующий ремонт в неверный checkout/rollback.
   Root CONTINUE.md отдельно начинает с C20/1.0.72. Решение: TD-129,
   одна очередь и current override в обеих точках продолжения;
   исторические записи и отрицательные результаты сохранить.
2. **Case identity тестовой очистки копируется вручную.** Старый helper
   жёстко выбирает `они должн ыбыть`, другой — непредварённую пару. Подмена
   селектора оставила ровно две собственные отрицательные записи и загрязнила
   последующие browser cases. Причина доказана сохранёнными receipts.
   Consumer проверяет путь receipt, но не доказанный cleanup status. Необязательный
   новый offline tool не устраняет этот обход. TD-130 открыт на этапе2 до
   привязки конкретного versioned caller; standalone selector не добавляем.
3. **Один bounded-tail invariant реализован дважды.**
   `preedit.rs::trim_tail_buffer` использует PREEDIT_TAIL_LIMIT=160;
   `tail_memory.rs::trim_committed_tail_buffer` содержит свой LIMIT=160.
   Оба обрезают Unicode scalar prefix. Новая first-word provenance отдельно
   предполагает tail<=160 для u8 offsets. Сейчас расхождения не найдено;
   риск — будущий односторонний ремонт. TD-131 устраняет копию, не расширяет
   лимит и не меняет scalar/byte units либо suppression-порядок.
4. **В WindowInteraction смешаны чистые предикаты и lifecycle/RPC.**
   `observation.rs` содержит 4325 строк: snapshot geometry, inert Reset
   witnesses, activation, word scope, callbacks, output settlement и types.
   Это несколько обязанностей под одним существующим owner. Однако выбранные
   retired-preedit функции уже образуют соседний pure block и имеют настоящие
   adapter no-mutation tests. TD-132 отложен до доказанной maintenance пользы;
   перенос ~100 строк ради размера не выполняется. TD-134 — оценка следующих
   границ после semantic map TD-136, без автоматической ownership миграции.
5. **Наблюдаемые ошибки быстрого Space ещё не имеют причинного доказательства.**
   GTK3 Entry получает `долженыбыть  `, Qt rich — `долженыбы ть ` в одном
   invalid-left control. Это факт результата, не доказательство виновности
   нового word lineage. Подобный ordering class есть и на b59. Возможные
   границы: raw clear/Reset, callback readiness, queued native key и CommitText.
   TD-133 требует первый нарушенный переход до любой production-правки.
6. **Legacy suppression без request identity всё ещё достижим.**
   `layout_controller.rs` выбирает LegacyV1, IME authority принимает no-arg
   SuppressNextAutocorrect. Текущие тесты фиксируют совместимость, не дают
   proof завершения synthetic input. Это остаётся TD-122, этап 2; слово
   legacy само по себе не разрешает удалять рабочий transport.
7. **Исследовательский и production API смешаны.** Некоторые eval части
   feature-gated; compiler/proof/orchestrator L2 и большой public re-export
   остаются в общей поверхности. Зависимости runtime от их типов ещё не
   измерены. TD-135 сначала строит reachability/package baseline; crate split
   и перенос моделей пока не рекомендованы.
8. **Большие тестовые файлы и текстовые structural guards имеют разные роли.**
   `adapter/tests/residuals.rs` — 13039 строк, terminal_delivery — 4159;
   большие proof/test файлы не являются runtime god-components. Structural
   `.contains()` проверки полезны для запрещённых owners, но не доказывают
   event order, effect count и поведение клиента. TD-136 требует semantic
   gaps/mutation evidence до изменения тестовых границ, сохраняя guards.
9. **Cleanup двух файлов не атомарен.** Оригинальный helper проверяет три
   baseline files, заменяет counters, снова сверяет journal, затем заменяет
   journal. В owning history зафиксирован CAS отказ уже после записи counters.
   Это отдельный доказанный partial-result class, не selector defect.
   TD-137 открыт на этапе2; dependent cases должны остановиться до exact
   recovery. «Тройной CAS» не называется общей транзакцией journal+counters.

Уже проверено отсутствие предполагаемого нового дефекта: first-word range
отзывается при trim/replacement в `advance_context_word_scope`; в manifest
есть `terminal_delivery_first_observed_word_range_is_revoked_by_navigation_backspace_and_trim`.
Не создаём задачу «исправить trimming provenance» из одного размера файла.
Неприменённые hypotheses не становятся bugs или runtime conditions.

## Конечный цикл выполнения

1. Plan review одним новым агентом без контекста: findings first, score 1–10,
   максимум первоначальный проход и один общий repair/final pass.
2. Перед production-правкой: task-local consequences, baseline/owner/first
   failure, варианты и граница rollback. Для extraction — characterize current
   semantics, не выдумывать RED от отсутствующего файла.
3. Tests/build/architecture refresh только remote по DEVELOPMENT.md и existing
   resource/Cargo guards. No new runner/owner/fallback. Runtime не устанавливать.
4. После каждого task — fresh-context независимый review, score 1–10, не более
   двух проходов. Score>=8 и отсутствие незакрытых correctness findings нужны
   одновременно; assessment не заменяет объективные gates.
5. Task получает DONE только в описанном scope, receipts/untested/runtime
   authority отдельно, commit/push, exact remote ref, затем следующий task.
6. После двух неудачных review passes — REPLAN_REQUIRED; assertions и canon
   не ослабляются. Сложный этап обсуждается отдельно, не маскируется DONE.

Функциональный proof существующей 1.0.81 остаётся исторически принят.
Исходники будущего refactor получают свои source/contract results; они не
наследуют установленную/оконную приёмку 2bd88 bytes.
