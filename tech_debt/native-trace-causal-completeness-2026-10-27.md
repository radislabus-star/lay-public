# Корректная граница чтения асинхронного журнала native-тестов

Статус: DIAGNOSTIC_FIX_ACTIVE. Код доставки и форматирование Lay не менять.

Production debug_log пишет асинхронно: active flush 1000мс, очередь4096,
принудительная запись после2048 строк. При выключении debug pending удаляется.
Раннер r18 читает файл сразу после строки и помечает trace_complete по одному
совпадению 12 строк-якоря. Это проверяет целостность якоря, а не полноту событий
конкретного сценария. Конечный native verdict из DOM+a11y сам по себе не меняется.

Минимальная правка диагностического wrapper: сохранять debug=true до окончания
сбора; дождаться записи и проверить наличие ожидаемой последовательности
ключей/идентичностей операции. Время ожидания само по себе не объявлять доказательством.
Неполный журнал отмечать отдельно; не выводить из него root cause и не менять
PASS/FAIL поля. Не менять темп самих жестов, цели, verifier или production flush.

Контроль: короткий заранее объявленный cohort всех9 lost-PASS selectors101/C,
по одному проходу каждой версии; полноразмерные матрицы сохранить как есть.
Документ владельца: docs/architecture/authenticated-revocation-retirement-2026-10-26.md.
