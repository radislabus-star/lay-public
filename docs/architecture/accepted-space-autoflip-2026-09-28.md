## Контракт для следующих изменений

После авторизованного исправления слова на Space окно видит правильное слово
и ровно один пробел. Режим Lay, выбранный GNOME source, фактический IBus
engine, `InputMode` и декодер следующей физической буквы должны соответствовать
исправленному слову. Смена GNOME и завершение запоздавшего IBus входят в одну
операцию `switch_complete_layout_stack`; она не даёт нового права менять
текст и не допускает второго инициатора. Потеря точного поля/слова отменяет
право на исправление. Лексическая догадка без verifier/SafetyGate не является
основанием для замены.

В существующих тестах этот контракт разделён по границам:

1. `tests/typing_assist_short_alternating.rs` и его TSV проверяют чередование
   коротких слов и сохранность чистого текста.
2. `state::tests::exact_legacy_autocorrect_selects_next_mode_before_missing_final_receipt`
   проверяет замену `дфн` на `lay ` и режим следующей буквы до позднего receipt.
3. `layout_sync::tests::space_layout_stack_completes_stale_ibus_once_in_both_directions`
   проверяет: после GNOME при старом или XKB IBus завершается ровно одна смена
   engine; при уже верном engine повторной смены нет. Этот тест использует
   только test-only подмену системных команд, не выполняет ввод в окно.
4. Только физическая матрица подтверждает видимый результат конкретного поля.
   Для новой версии старый receipt не переименовывается в новый PASS.

`scripts/check_architecture_canon.py` требует новое решение для изменения
владельцев этого маршрута, его тестов, fixture, test manifest и данного
контракта. Решение указывает затронутые C09/C10, новый source gate, при
изменении установленного IME — новый физический receipt и непроверенные поля.
Отдельно проверяются `дфн ` → `lay `, `max`, обратное направление RU/EN и
следующая буква. Не добавлять буквальные слова или клиентские исключения в
runtime для прохождения этих примеров.
