# Lay 1.0.100 — сохранение событий при повторном переключении и смене фокуса

Исправлены два подтверждённых сбоя общего механизма IME:

- Во время точного native replay промежуточное обновление текста могло прийти
  раньше обновления позиции курсора. Теперь уже наблюдённый ввод сохраняет
  ожидающее подтверждение происхождение текста. Новое изменение по-прежнему
  требует точного конечного текста и курсора.
- При уходе из поля с незавершённой IME-композицией очистка старого слова
  стирала уже полученное событие следующего фокуса. Теперь старое слово и его
  разрешения отзываются, а новое поле проходит обычное получение контекста.
  Сохранённое событие фокуса само по себе не разрешает изменять текст.

Маршруты доставки, проверка права на изменение, модели и обучение сохранены.
Ручная установка или перезапуск локального GNOME не выполнялись.

Проверены 3519/3519 Rust-проверок корректности и пакетов,11/11 проверок
производительности, Python419 с10 пропусками и без ошибок, строгие проверки
Rust, обе конфигурации MSRV1.88 и все10 оптимизированных программ.

Относительно1.0.98 получено на7 PASS больше. При этом12 прежних PASS стали
FAIL в данном прогоне; все переходы сохранены. Это поставка двух ограниченных
исправлений, а не подтверждение отсутствия регрессий или полной совместимости.
Остаются отказы быстрой серии Double Shift, готовности подсказки и некоторых
Space-коррекций. BLOCKED не считается исправленным сценарием.

Chrome — медиана47,8мс,p9564,8мс,366 замеров в111/220 сценариях.
Сценарии без успешного наблюдения цели в эти задержки не входят.

Дополнительные короткие проверки терминалов: Kitty5/5 PASS,Konsole5/5 PASS,
WezTerm0/5 PASS. Терминальные пять переключений ожидают каждую цель и не
равнозначны браузерной быстрой серии. У Kitty/Konsole на сохранённых кадрах
набранный префикс обычный, продолжение выделено белым фоном. Позднейшая
диагностика WezTerm приняла Tab, но видимое продолжение отсутствовало;
первоначальные FAIL и ошибка отображения остаются открытыми.

После полной матрицы у той же тестовой службы снят старый лимит одного CPU
по разрешению владельца выделенного стенда. PID и байты IME сохранены.
Короткий отдельный прогон с20CPU: Firefox12P/6F/2B,Chrome16P/2F/2B из20
каждый. Эти40 сценариев не заменяют полную матрицу и не доказывают, что
ограничение CPU было причиной всех отказов. Ресурсы пользовательских установок
этой настройкой тестового стенда не изменяются.
