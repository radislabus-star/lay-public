## 3. Critical Review Of The Initial V80 Sketch

### 3.1 Decoded segment canonicalization was overstated

The package compiler already constructs one globally sorted and deduplicated
`SEGMENT_POOL`. Inside one validated package, equal `segment_ref` values imply
equal normalized UTF-8 payloads, and unequal references imply unequal payloads.
Decoding every segment merely to replace one canonical identity with another
would add work without increasing equivalence.

Across different packages, references are not comparable. V80 operates over
one checked package generation, so package identity belongs to every prepared
semantic index and cache key.

### 3.2 V70 includes non-execution identity in its key

`TERMINATE(slot_id, variant_id)` emits no scalars. `slot_id` affects the output
relation and must remain in the execution key. `variant_id` attributes a
terminal identity but does not affect generated bytes. V70 includes the full
terminate operation, so output-equivalent programs with different variants are
needlessly separated.

V80 must separate:

```text
execution semantics -> generated normalized bytes and target slot
owner attribution   -> paradigm, variant, evidence, stability, provenance
```

Owner attribution is never merged into execution evidence.

### 3.3 Operation-byte equality is sufficient but not complete

Two different valid operation sequences can describe the same deterministic
source-to-output function. Examples include adjacent emitted runs and different
instruction decompositions around one retained source edge. Raw operation-byte
identity therefore misses safe sharing.

The replacement key must be a canonical symbolic transduction, not an
approximate hash and not a linguistic suffix rule.

### 3.4 An output index cannot be fully static

Generated surfaces depend on the recovered anchor surface. A package cannot
precompute every possible `(slot, output surface)` for unseen anchors. The
package may precompute semantic transforms and their owners; the exact output
index is built transiently for the current recovered anchor.

### 3.5 Bitsets can move the problem into memory

A dense bitset for every transform, slot, POS basin, and package relation can
exceed the current package and constant-cache budgets. The estimator must
compare dense, sparse ordered, and hybrid representations using actual owner
cardinalities. No representation is accepted because it is theoretically
fast.

### 3.6 Constraint-first rejection needs complete alternatives

A paradigm may own multiple programs for one target slot. Failure of one
program is not failure of the slot. Early rejection is exact only after every
semantic alternative belonging to that owner for the selected exposed
constraint has failed.

### 3.7 Cache is not a cold-path proof

A cache can accelerate repeated damage classes, repeated typing, and repeated
phrase contexts. It does not improve the first request. Fixed quality and cold
latency are measured with the cache empty; warm-cache speed is a separate
denominator.

### 3.8 Proof throughput is not product latency

Twenty proof workers measure throughput. They do not prove one-request latency.
V69/V70 exact replay occurred outside the old closed-call timer. V80 must report
end-to-end cold binding latency including hypothesis preparation, semantic
execution, owner-set algebra, candidate materialization, and readout.

## 4. Canonical Execution Semantics

### 4.1 Symbolic output pieces

Every transferable program is normalized into an ordered sequence:

```text
SourceSlice(start_expression, end_expression)
Literal(segment_ref)
```

plus:

```text
source-length validity guards
target_slot_id
```

`start_expression` and `end_expression` are canonical start-relative or
end-relative scalar expressions. `COPY_TO_RETAINED_EDGE`, edge drops, and
replacement ranges are resolved into these expressions. A replacement becomes
source consumption in the guards plus an optional `Literal` output piece.

Adjacent literals are canonicalized to their actual concatenated UTF-8 bytes.
Because the global segment pool may already contain the maximal emitted run,
the estimator may reuse that reference; otherwise the canonical key stores the
checked byte sequence without mutating the package.

`TERMINATE.variant_id`, support, stability, provenance, phase evidence, and
paradigm identity are excluded from execution semantics and retained in owner
records.

`EMIT_EXACT_ALLOMORPH` is forbidden in transferable semantic transforms, as it
already is in direct replay.

### 4.2 Equivalence theorem

For one validated package generation, two transferable programs are execution
equivalent when their canonical source-length guards, ordered output pieces,
and target slot are byte-equal.

For every normalized source satisfying the shared guards, both programs append
the same source scalar slices and the same literal UTF-8 bytes in the same
order. They therefore produce the same normalized output bytes and terminate
at the same target slot. This equivalence shares execution only; each original
program retains its independent owner attribution.

The implementation may use a cryptographic or fast hash to find a candidate
bucket, but full canonical bytes must be compared before sharing execution.

## 5. Package-Time Prepared Field

The read-only estimator first models these sections without writing a package:

```text

  canonical output-piece range
  target slot

SemanticOwnerPosting
  semantic transform id
  paradigm id
  original program id / variant id
  evidence attribution refs

  anchor slot
  target slot

```

The existing productive `.p2m` and recovery `.p2r` remain the authority source.
Any future semantic sidecar is derived, checksummed against both package hashes,
mmap-safe, deterministic, and rebuildable. A corrupt or mismatched sidecar
fails closed to the unchanged package path; it never silently changes owners.

## 6. Runtime Contour

### 6.1 Hypothesis grouping

Deduplicate recovered hypotheses by exact:

```text
(package generation, POS, anchor slot, normalized anchor surface)
```

Independent source support remains attached to the hypothesis and is copied to
each proven owner candidate after exact reconstruction.

### 6.2 Exact invariant filter

For every anchor surface, eliminate only mathematically impossible transforms:

```text
source length violates the canonical guard
generated length cannot equal any expected surface length for the target slot
fixed literal prefix/suffix contradicts the expected bytes
target slot is not exposed
```

The filter has no learned threshold and no top-k. Every rejected transform must
carry a typed impossible reason that can be replayed by a reference executor.

### 6.3 Shared DAG execution

Execute each surviving canonical output-piece prefix once. Source slices and
literal runs shared by descendants are emitted once into a bounded scratch
buffer. Every terminal produces:

```text
(semantic_transform_id, target_slot_id, exact normalized output)
```

No paradigm owner is visited during string construction.

### 6.4 Transient exact output index

For the current anchor only, exact terminal outputs are matched against exposed
constraints:

```text
(target_slot_id, exact output bytes) -> semantic transform ids
```

Nonmatching outputs are discarded before owner expansion.

### 6.5 Owner-set algebra

For each required exposed `(slot, surface)` constraint, union the owners of all
matching semantic transforms. Intersect those owner sets across every required
constraint:

```text
owners = owners(constraint_1)
       AND owners(constraint_2)
       AND ...
       AND owners(constraint_n)
```

Multiple exposed surfaces in one slot remain multiple required constraints,
matching the current `matched_count == exposed.surface_count` contract.

Constraint evaluation order may use measured posting cardinality to minimize
work. Set union/intersection is associative and commutative, so ordering cannot
change the final owner set.

### 6.6 Candidate fan-out

Only surviving owner IDs are expanded into `RecoveredAnchorCandidateV1`.
Original paradigm evidence, stability, provenance, variant identities, and
independent sources are restored from owner postings. Existing deterministic
evidence order and `PRODUCTIVE_PHYSICAL_TOP_K=32` remain unchanged.

## 7. Work Model

V70 work is approximately:

```text
sum(hypothesis x transition class x relevant program)
```

V80 work is measured separately as:

```text
semantic transforms surviving exact invariants
semantic DAG arcs traversed
normalized scalars emitted
exact terminal comparisons
owner-bitset machine words unioned/intersected
final owner candidates materialized
```

These denominators must not be collapsed into one misleading number. In
particular, a bitset `AND` over one machine word is not equivalent to executing
one morphology program, and neither is a CPU instruction count.

## 13. Lossless Indexed Executor Amendment

Before executing strings, package-derived transforms are partitioned by:

```text
(POS, source slot, target slot, affine output-length shape)
```

For every canonical transform, output scalar length is an exact affine
function of source scalar length:

```text
output_len = source_coefficient * source_len + constant
```

The coefficient and constant are derived from the same checked copy ranges,
retained edge, replacement boundary, and literal UTF-8 scalar counts used by
the reference executor. This is not a learned estimate. A transform is skipped
only when its exact output length cannot equal any exposed surface length for
that target slot.

If a canonical transform begins or ends with a fixed literal, exact expected
bytes must have that prefix or suffix. This edge check is also a necessary
condition, not a ranking heuristic. Interior literals remain subject to full
reference execution and exact output equality.

Owner sets are accumulated as sorted sparse owner IDs. Constraint lists are
intersected in increasing cardinality order. This preserves the same set
because set intersection is associative and commutative; no owner is removed
before an exact constraint contradiction.

## 15. Pre-Implementation Surface And Lane Theorem

The diagnostic receipt confirms two independent structural causes inside the
four born-but-displaced suffix cases:

```text

```

The next runtime change is therefore fixed before compilation.

Within each rank-origin lane, the physical readout key becomes:

```text

```

The node retains the complete sorted set of original
`ProductiveCandidateIdentityV1` values. Distinct slots, paradigms, programs,
variants, owners, and evidence attribution remain recoverable from that set.
Only the repeated display position is removed. Base and recovered lanes remain
separate until the existing composite surface grouping, so the base projection
can still be compared exactly and a recovered relation cannot consume a base
position.

```text

```

This is the cross-lane certificate. It is not a score threshold and does not
use the heldout target. Certified recovered and base nodes share the existing
score/evidence/geometry total order. Uncertified recovered nodes remain after

For every terminal generated from one `(binding, slot profile, scene)`, the
runtime recomputed all of the following:

```text
lemma, paradigm, slot, and directional count evidence
four centered logarithm pairs
directional residual binary search
positive, anti, and hard-negative phase cosine banks
```


feature extraction because no feature transform depends on another feature.

### 18.2 Candidate surface buffer reuse

The next inspected general repetition is allocation before bounded retention.
Direct packaged replay reuses one output `String`, but previously cloned it
into every one of the `210,302` logical terminal candidates before knowing
whether the per-slot frontier would retain that candidate. A full frontier
then discarded or replaced the candidate and freed its allocation.

The lossless amendment moves the current output buffer into the candidate.
Bounded retention returns the buffer owned by a rejected or replaced candidate
for the next program execution. A newly retained candidate consumes one buffer;
all subsequent rejected or replacing candidates reuse an existing allocation.
Candidate identity, score, geometry, ordering, frontier capacity, `top_k`, and
surface reduce are unchanged. Acceptance requires the same exact parity counts
listed above and a lower one-worker maximum class p99 before any full proof.

### 18.3 Request-local post-selection buffer pool

Criticism of the rejected V85 mechanism found that it returned a buffer only
when one per-slot frontier was already full. Most terminals occupy distinct
slot frontiers and are removed later, when the runtime selects the best sixteen
slots. V85 therefore added ownership movement without recycling the dominant
set of discarded surfaces.

The corrected experiment keeps one bounded surface-buffer pool for the complete
`evaluate_checked` call. It receives buffers from both locations:

```text
immediate per-slot duplicate/replacement/rejection
all candidates belonging to slots rejected by final geometry selection
```

The next binding takes its execution buffer from this pool. Slot-leader sorting
also uses references rather than cloning complete candidates and their strings.
The pool cannot grow without bound across requests: it is request-local and its
cardinality converges to the maximum discarded frontier of one active binding.
Selected candidates retain their own strings exactly as before. Candidate
identity, score, ordering, slot selection, `top_k`, proof denominator, and
authority are frozen. The experiment is accepted only by exact parity and a
lower measured maximum class p99.

### 18.9 V91 source-group scratch theorem

The required symbolized V90 profile was captured from a separate release build
with the same `opt-level=3`, LTO, one codegen unit, and runtime source; only
symbol stripping was disabled. It rejects a second frontier rewrite as the next
experiment:

```text

fixed-point score self                                     0.08%
ranked-candidate small sort self                           0.10%
malloc/free/realloc family self                    materially larger
String scalar extension self                               3.75%
```

The profile includes proof and grounding work, so allocator percentages are
diagnostic and cannot by themselves authorize a runtime change. Source
inspection identifies a narrower exact repetition inside the closed readout:
V90 sorts accepted bindings by exact `normalized_source`, but every binding
still rebuilds the same `Vec<char>` and creates a new output `String`. The slow
rows repeat one source across `55-76` active bindings.

V91 therefore changes scratch ownership only:

```text
exact source group
-> decode normalized source scalars once into reusable Vec<char>
-> keep one reusable output String for class misses
-> each binding traverses every original owner program
-> dense execution lane still stores success/failure, Arc surface, geometry
-> every owner still receives independent terminal, slot, score, and frontier
```

This is exact because both scratch values are overwritten before their next
semantic use. Accepted cached surfaces have independent request-local `Arc<str>`
ownership before the output string is cleared. A source change resets the dense
execution lane and source scalars together. The non-semantic oracle path also
refreshes scratch on every source change, so this amendment does not make
source-major ordering a hidden requirement.

V91 is forbidden from changing owner count, candidate identity, score,
geometry, ordering, slot capacity, `top_k`, package bytes, corpus, coefficients,
authority, SafetyGate, verifier, or proof denominator. Acceptance requires
