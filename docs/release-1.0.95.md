# Lay 1.0.95 — разделение сред и исправления KDE

Выпуск публикует накопленные изменения текущей ветки. Полная работоспособность
Lay во всех окнах KDE не подтверждена; известные отказы перечислены ниже.

## Изменения

* Особенности KDE собраны в отдельном модуле IME. Выбор среды отделён от общих
  правил владения словом, проверки операции и доставки текста.
* Исправлена потеря связи с тем же полем Chrome при обновлении нативных
  уведомлений. Уточнена обработка устаревших результатов, чтобы они не
  отзывали более новое владение текстом. Это улучшило повторный Double Shift
  в контрольных полях Chrome.
* Ограничено число подключений к нативной шине наблюдения. Отменённые операции
  освобождают свои ресурсы; причины отказа сохраняются в диагностике.
* Уточнены настройка IME для приложений и управление демоном из меню KDE.
* В KDE-трее меню явно связано с `QSystemTrayIcon`. Проверен экспорт реальных
  действий через DBus. Это исправление экспорта, а не подтверждение успешного
  клика в любой сессии Plasma: сообщение пользователя о неработающем значке
  остаётся открытым.

## Фактическая проверка и ограничения

Последний полный контрольный прогон Chrome на частной сборке 1.0.94.1 с тем же
функциональным Rust-кодом: **172 PASS / 9 FAIL / 39 BLOCKED из 220**. У трёх
групп ручного переключения — обычного туда/обратно, двух последовательных
переключений и серии из пяти — нет FAIL, но остаются BLOCKED. Девять FAIL
приходятся на исправления по пробелу: три переключения EN/RU и шесть переносов
ошибочной границы двух слов. Настоящая адресная строка Chrome проверяется
отдельно; подсказка второго слова остаётся открытой задачей.

Один последующий контроль в новом профиле Chrome прошёл. Контроль Firefox
остановился до ввода из-за неоднозначной идентификации нативного приложения;
это BLOCKED, не успешная проверка Firefox. Нового полного прогона GNOME нет.

В обычном профиле пользователя остаются сообщения об отсутствии подсказки,
Tab, Double Shift и реакции значка трея. Результаты нового контрольного профиля
не закрывают эти сообщения. Сбой обновления изображения Remmina исправлялся
отдельно и не является доказательством работоспособности Lay.

В ранее выполненном прогоне исходников: 630 PASS и 15 известных базовых FAIL;
отдельно сохраняется ошибка проверки покрытия TD-121. Целевые проверки
нативного адаптера и разделения сред прошли. Для управления KDE-демоном:
7 PASS / 1 SKIP. Смена номера версии не является новым нативным испытанием.

## Обновление

Релиз распространяется через существующий пункт «Проверить обновления» и
включённое пользователем автообновление. Источником версии служит стабильный
публичный тег `v1.0.95`. Публикация сама по себе не является ручной установкой
или перезапуском текущего сеанса ввода.

## Проверки GitHub после публикации

Проверки установщика и минимальной версии Rust прошли. Основной
[CI](https://github.com/radislabus-star/lay-public/actions/runs/40089564155)
скомпилировал тестовые цели, затем остановился на несовпадении реестра тестов
с фактическим составом. Полный CI не прошёл.

[Security](https://github.com/radislabus-star/lay-public/actions/runs/40089564154)
также завершился отказом аудита зависимостей. В журнале есть замечания RustSec
для rustls-webpki, webpki-roots, tokio и предупреждения о zvariant. Зависимости
в рамках публикации не обновлялись, исключения аудита не добавлялись.

После публикации установленные обновляторы GNOME и KDE успешно обнаружили
переход 1.0.94 → 1.0.95. Это проверка обнаружения релиза; автоматическая
установка новой версии этим результатом не подтверждается.
